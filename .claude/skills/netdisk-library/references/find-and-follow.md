# 找片 / 追更

入口是 `netdisk-library` SKILL.md 的分诊表；这里是「补齐一部剧」那一档的落地判断。
工具的字段与契约在它们自己的描述里，这里只写**描述里没有的判断**。

## 1. 先看，再决定要不要找

顺序是死的：`netdisk_bindings` 拿 setId → `netdisk_follow` 的 `view`。

`view` 一次给齐三样：`missingAired`（**已播出且还没拿到**的那几集，这是唯一要看的数字）、
`shares[]`（这条绑定已经知道的分享和它们的验活结果）、`lastRuns[]`（最近五轮各干了什么）。

**`missingAired` 为空就停下来说"齐了"，不要去 `video_search`。** 这一步最容易被跳过，因为
"用户让我补齐"听起来像是"去搜"。搜一轮死链再报告，比直接说"已经齐了"糟得多。

`upcoming` 是还没播的，不是缺口；`airDate` 缺席的集**不算已播出**（TMDb 没给日期时宁可漏追，
不能拿"没日期"当"还没播"，也不能当"已经播了"去瞎搜）。

`lastRuns[0]` 要老实读：`saved > 0` 而 `synced.matchedAfter` 没变，意思是**文件到了但还没被认成集**
（夸克还在搬，或文件名里没有能认的集号）——这既不是成功也不是失败，就这么说。
一轮什么都没做成时，只有 `lastRuns[0].errorList[]` 能解释为什么。

## 2. 「这部剧我要」= enable + run，而 run 是真写盘

`netdisk_follow` 的 `run` 会：回访已知分享 → 搜新的 → **把选中的文件转存进用户自己的网盘** →
重新匹配 → 归档，且归档带 `losers:true`，**把同集的落选副本删进网盘回收站**（夸克约 10 天可捞）。

所以：**先把这几件事告诉用户、拿到他的同意，再调 `run`。** 不要为了"看一眼"去调它——看一眼是 `view`。

它**立刻返回** `{started:true}`，只说这一轮开始了。一轮大约 1–3 分钟。
**不轮询、不发第二次 `run`**：等约两分钟，`view` **一次**，读 `lastRuns[0]`。
已经在飞的一轮会让第二次 `run` 回 `{started:false, alreadyRunning:true}`——那不是错误，等就是了。

`archived.gated` 表示健康闸**故意**挡下了归档那一步（权威清单当时不健康），不是失败。
`archived.runId` 要留着：这一轮归错了就用 `reconcile_undo_run` 整轮撤回。

## 3. 老剧的分享几乎全是死的，这是常态不是故障

一年以上的老剧，`video_search` 搜出来的链接大部分已经失效。**逐条 `netdisk_share_verify`**，
别把搜索结果直接当成"找到了"递给用户。

`validity` 五档，别混：

- `alive` —— 能用。
- `not-usable` —— 已删除或被下架。**对非在播剧这是正常结果**，不值得重试，也不要写成"出错了"。
- `needs-login` —— 账号打不开（缺提取码，或缺用户的登录态）。
- `unknown` —— 这次检查本身没拿到答案。**不许报成死链。**
- `unsupported` —— 我们查不了这一条（非夸克网盘，或者根本不是分享链接）。也不许报成死链。

两条配套的：`video_search` 里 `needsResolve:true` 的条目是**落地页不是网盘链接**，先 `video_resolve`
拿到真链再验；`files` 列表封顶 200 条，`truncated:true` 时**不能**从一份被截断的清单里断定某集不在。
百度 / 阿里的链接我们不转存，如实说，别让用户空等。

## 4. 分享全死了怎么办：什么时候该放弃找分享

判据是**已知分享全部 `not-usable`，且按季搜过之后新分享也全部 `not-usable`**。到这一步就停，
别一季一季反复搜——搜索走的是同一批源，换个词不会变出活链接。

出路是官方渠道：正片常常挂在 WeTV / 腾讯的官方 YouTube 播放列表里。但这条路**手边没有 shell 时做不了**
（要 yt-dlp + cookie + 直连 AList 上传）。那种时候要做的是：
**说清楚这条路存在、说清楚它得在 Claude Code 里做**，然后把决定交回用户，不要假装尝试。

真去做那一步时（Claude Code 侧），只有一条判断属于这里：**上传的文件名只留集号**，
例如 `S02E24.mp4`。理由是归档器给认领的集加 `SxxExx - ` 前缀、并且把文件名当证据读——
名字里多带一段标题或来源，只会给后面的匹配添一个要绕的坑。

## 5. 缺集数对不对，先看播出日期，不看集号公式

一期两集的综艺（上 / 下）在 TMDb 上是两条：第 N 期 → `E(2N−1)` 和 `E(2N)`。
一旦某一期有上中下三段，从那一期往后整体偏移 1。**所以不要用公式反推"应该有多少集"**——
用 `netdisk_sync` 的 `bySeason`，它按季给 `matched / total / unaired / missing`，`missing` 里每条带 `airDate`。
拿日期对，不拿算术对。**`total` 只数已播出的集**：还没播 / 未定档的占位在 `unaired` 里，既不在 `total`
也不在 `missing`——「97/97，另有 4 集未播」就是一集不缺，别把 `unaired` 报成缺口。

（`missing` 每季封顶，`missingTruncated` 说什么时候还有更多——被截断的清单不是完整缺口。）

## 6. 「第N期」和 `SxxExx` 不是一回事

期号体系是节目自己的编号，集号体系是 TMDb 的。文件名里只有「第N期」时，认集靠的是
**季文件夹**加上「上 / 下」分段——这也是为什么转存的落点是分享同名子文件夹而不是作品根目录：
根目录里可能已经躺着别季的「第7期上」。

**认错了长什么样：整季从 E02 起集体错位一位**（不是零散错几个）。
这时候**不要去改文件名**——名字改了就成了下一轮的证据，错误会被水泥封进去。
去 `diagnose-netdisk-match` skill：那条线改的是匹配器的判据，并把这个案例钉成回归测试。
